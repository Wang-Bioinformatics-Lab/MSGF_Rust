# Licensing — what is in this repository, and what deliberately is not

MSGF_Rust is a clean-room reimplementation of MS-GF+'s significance scoring. MS-GF+ itself is
**Copyright The Regents of the University of California**, licensed for educational / research /
non-profit use with attribution — commercial use requires a UCSD Technology Transfer agreement.
That is not an OSI licence, so a project that *ships* UC-derived bytes cannot be MIT.

This repository ships none. It is MIT (see [`LICENSE`](LICENSE)), and this document is the record
of how that was achieved and what remains true.

## 1. What MSGF_Rust distributes

| Artifact | Origin | Licence |
|---|---|---|
| All Rust source (`rust/crates/**`) | written here | MIT |
| The bundled scoring model `rust/crates/msgf-scorer/models/MSGFRust_HCD_HighRes_Tryp_v1.param` | counted by our own `msgf-train` from MassIVE-KB (MassIVE `MSV000081142`) | model: MIT; corpus: **CC0 1.0** |
| Docs, plans, scripts (`docs/`, `validation/*.py`, `validation/*.sh`, `validation/reference/**`) | written here | MIT |
| `validation/golden/chemistry/**` | computed from published physical constants by our own Python | MIT |
| `validation/golden/models/param_inventory.golden.json` | file sizes / SHA-256 / identity strings of `.param` files — a manifest, no trained numbers | MIT |

The **default scoring model is the CC0-trained one**: `msgf search` and `msgf rescore` work with no
`--param`, and nothing on that path touches a UC artifact. Provenance and quality measurements:
[`rust/crates/msgf-scorer/models/README.md`](rust/crates/msgf-scorer/models/README.md) and
[`docs/training.md`](docs/training.md).

## 2. What is *not* distributed (and how to get it)

Everything below is UC-derived. It is used for validation only, fetched or generated on your
machine, and excluded by `.gitignore`.

| Not committed | What it is | How to obtain |
|---|---|---|
| `validation/data/**` | MS-GF+ test spectra, FASTAs, config, and its trained `.param` models | `validation/fetch_reference_data.sh [--full] [--jar]` |
| `validation/reference/MSGFPlus.jar` | the MS-GF+ release jar (the numeric oracle) | `fetch_reference_data.sh --jar` |
| `validation/golden/iprg2013_F13.*`, `rawscore/**`, `worked_example.golden.json` | frozen outputs of *running* MS-GF+ | `validation/reference/build_all_golden.sh` (needs Java) |
| `validation/golden/spectra/**` | parse facts about UC test spectra — these embed peak values from `F13.mgf` | `validation/reference/make_spectra_golden.py` |
| `validation/golden/models/*.model.golden.json`, `models/node_scores.golden.json` | samples of UC's *trained tables* and scores derived from them | `validation/reference/make_model_golden.py`, `make_nodescore_golden.py` |
| `validation/golden/fdr/**` | `TargetDecoyAnalysis` q-value maps dumped straight out of the MS-GF+ jar | `validation/reference/make_fdr_golden.sh` (needs the jar; no spectra or database) |

Note `validation/data/training/**` is also uncommitted, but for size, not licence: it is the CC0
MassIVE-KB corpus (~950 MB), fetched with `fetch_reference_data.sh --training 20`.

### The 2026-07-24 cleanup

The golden JSON in the last three rows **used to be committed** (~5.2 MB). It was untracked on
2026-07-24 as part of making the repository MIT-clean; the files themselves are unchanged and are
regenerated by the scripts above. `validation/golden/UC_DERIVED.sha256` records what each file
hashed to at that moment (MS-GF+ v2024.03.26), as provenance evidence.

Consequence to be aware of: **the golden-backed tests now skip on a clean checkout.** `cargo test`
passes either way (verified: 134 tests pass with the goldens present and with them absent), but a
checkout that has not run `fetch_reference_data.sh` + `build_all_golden.sh` is validating the
algorithms, not the bit-exactness. Run `cargo test -- --nocapture | grep 'skip:'` to see what was
not checked.

**Git history still contains the removed files.** Untracking stops future distribution; it does not
rewrite the past. Release tarballs, `cargo package` output and fresh clones of the current tree are
clean, but `git log`/old tags are not. Purging them entirely would require a history rewrite
(`git filter-repo`), which invalidates every existing clone and the merged PR history — a call for
the maintainer to make deliberately, not a side effect of this cleanup.

## 3. The clean-room boundary

Reproducing MS-GF+'s *arithmetic* is the job of the scorer and the DP, and that work reads the Java
freely — algorithms and file formats are interfaces, not protected expression. Two paths are held
deliberately separate from it:

- **The `.param` encoder** (`msgf-scorer/src/write.rs`) is written from
  [`docs/param-format.md`](docs/param-format.md), not transcribed from
  `NewRankScorer.writeParameters`.
- **The trainer** (`msgf-train`) defines its statistics from how the *scorer consumes* each table,
  never from `ScoringParameterGeneratorWithErrors`. See `docs/training.md` § "Clean-room boundary".

Two tests enforce that the authoring path needs no UC bytes at all:
`msgf-scorer::author_a_model_from_scratch` and `msgf-train::trains_a_scoring_model_from_scratch`
build, write, re-read and score a model from synthetic data on a clean checkout.
