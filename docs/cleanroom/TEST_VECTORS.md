Every set here was produced by the oracle in `../oracle_bin/` using the bundled model
`../model/MSGFRust_HCD_HighRes_Tryp_v1.param` (SHA-256 `5f6ab76f…2d02`). The exact commands are
listed under each set. The acceptance criteria are in `../SPEC.md` §11.

## inputs/

| file | content |
|---|---|
| `psms_hela.tsv` | 17,724 PSMs (see below) |
| `psms_hela_intermediate60.tsv` | the PSMs of 60 randomly chosen (scan, charge) groups (seed 3); the input of `intermediate/hela60_*` |
| `psms_synthetic.tsv` | 38 PSMs against `synthetic.mgf` |
| `human_aa_probs.tsv` | residue composition of UniProt UP000005640 (human, 20,652 proteins, FASTA SHA-256 `2329a517…84d5a0`): count of each of the 20 letters ÷ total of the 20 letters |
| `make_synthetic.py` | the synthetic generator |

`psms_hela.tsv` has the header `scan, peptide, charge, origin`. It holds 17,724 PSMs:

- **14,764 `search_hit`**: the top 5 per spectrum from `search_hela_r01`, targets and decoys.
  Modification deltas are 3-decimal strings, `C+57.021` and `M+15.995`.
- **2,960 `shuffled_decoy`**: one per (scan, charge). The top hit's residues are shuffled, with the
  flanks and C-terminal residue kept (seed 20260930).

## rescore/ — final scores (`msgf rescore`)

Columns: `scan, peptide, charge, raw_score, denovo_score, spec_evalue`, in input order.
`*.stderr` holds the skip reasons.

| file | PSM list | null alphabet (SPEC §8.2) | isotope range |
|---|---|---|---|
| `hela_uniform_ti0_1.tsv` | psms_hela | 20 unmodified residues, w = 0.05, π = 0.1 | 0,1 |
| `hela_uniform_ti0_0.tsv` | psms_hela | same | 0,0 |
| `hela_uniform_ti-1_2.tsv` | psms_hela | same | −1,2 |
| `hela_composition_oxm_ti0_1.tsv` | psms_hela | 20 unmodified residues with `human_aa_probs`, plus `M+15.994915` (w_M), π = w_K + w_R | 0,1 |
| `synthetic_uniform_ti0_1.tsv` | psms_synthetic | uniform | 0,1 |
| `synthetic_uniform_ti-1_2.tsv` | psms_synthetic | uniform | −1,2 |
| `synthetic_composition_oxm_ti0_1.tsv` | psms_synthetic | composition + oxM | 0,1 |

Rules that apply to every rescore set:

- **Alphabet order**: `G A S P V T C L I N D Q K E M H F R Y W`, then oxM if present. C is
  **unmodified** (103.00919) in every rescore null alphabet. A PSM with `C+57.021` is still scored
  (RawScore) with C at 160.
- **N-terminal context** comes from the peptide string (SPEC §7.3, rescore mode): flank K, R or
  `-` gives credit, any other flank gives the penalty, and a bare string gives credit.
- **Coverage**: each hela set covers 2,960 (scan, charge) groups. 58, 54, 75 and 58 PSMs
  respectively have RawScore > DeNovoScore and therefore SpecEValue 0 (printed `-0.000000e0`).

Commands:

```
S=spectra/hela_r01_sub.mgf; I=inputs/psms_hela.tsv; O=../oracle_bin/msgf
$O rescore -s $S -i $I -o rescore/hela_uniform_ti0_1.tsv
$O rescore -s $S -i $I --ti 0,0 -o rescore/hela_uniform_ti0_0.tsv
$O rescore -s $S -i $I --ti -1,2 -o rescore/hela_uniform_ti-1_2.tsv
$O rescore -s $S -i $I --aa-probs inputs/human_aa_probs.tsv --ox-m -o rescore/hela_composition_oxm_ti0_1.tsv
# synthetic: same with -s spectra/synthetic.mgf -i inputs/psms_synthetic.tsv
```

## search_hela_r01/ — search mode (`msgf search`)

```
msgf search -s spectra/hela_r01_sub.mgf -d UP000005640_9606.fasta --tda --fixed-mod C+57.021464 \
    --var-mod M+15.994915 -t 10ppm --ti 0,1 -c 2 -n 5 --threads 16 -o search_n5.tsv
```

The run took 3 s and produced 14,764 PSMs, 8,323 of them targets. 1,265 target PSMs pass 1 % FDR.
The FASTA is not included (UniProt, 14 MB). The hash is given above, and decoys are the reversed
protein sequences with prefix `XXX_`.

- `search_n5.tsv`: the MS-GF+ column set, up to 5 PSMs per spectrum. `MSGFScore` = RawScore.
- `search_n5_context.tsv`: the same PSMs, pre-digested for your API.
  - `residues_full_precision`: the core sequence with the deltas actually scored (57.021464, 15.994915).
  - `n_term_credit`: 1 if the preceding residue is K/R, the peptide is at the protein N-terminus,
    or it follows an initiator Met. Computed from the first listed protein.
  - `context_ambiguous`: 1 if different occurrences of the peptide disagree on N-terminal credit
    (25 rows). Skip these; the oracle scored one unspecified occurrence.
  - `is_decoy`, `MSGFScore`, `DeNovoScore`, `SpecEValue`.

Null alphabet for this set:

- the 20 residues in the order above, C at 57.021464 + 103.009185, with `human_aa_probs`;
- plus `M+15.994915` with w_M;
- π = w_K + w_R;
- isotope range 0,1.

RawScore, DeNovoScore and SpecEValue of every non-ambiguous row follow from SPEC §3–§8. This was
checked on the spec side for a random 50-group sample, 246 PSMs including decoys, with no
differences.

## intermediate/ — per-stage values (`msgf-oracle-dump`)

| file | groups | alphabet |
|---|---|---|
| `hela60_composition_oxm_ti0_1.jsonl` | 60 real (scan, charge) groups, 360 PSMs | composition + oxM, C unmodified |
| `synthetic_uniform_ti0_1.jsonl` | 16 synthetic groups (9010 skipped), 35 scored PSMs | uniform |

JSON-lines format. f32 values are printed shortest-round-trip: parse them as f64, then cast to f32
before comparing.

**Line 1** is `{"type":"alphabet","mixture_pi":π,"aa":[{"residue","nominal","mass_f32","prob"}…]}`.
The array is in edge order.

**Every other line** is `{"type":"spectrum", …}` with these fields:

| field | meaning (SPEC section) |
|---|---|
| `scan`, `charge`, `precursor_mz` | inputs |
| `M_parent` | M (f32), §3.1 |
| `N0` | N₀, §3.1 |
| `skipped` | present if N₀ is out of range |
| `sinks` | §8.1, ascending |
| `input_peak_count` | count before preparation |
| `final_peaks.{mz,intensity,rank}` | the final peak list Π, §3.2–3.5 |
| `partition_by_segment[s]` | `{sorted_index, z, boundary, segment}`: the partition chosen for segment s, with its index in the (charge, segment, boundary)-sorted list, §4.1 |
| `rho` | ρ, §4.4 |
| `anchor_is_prefix` | polarity of the anchor type, §4.5 |
| `edge_const_none`, `edge_const_cur`, `edge_const_prev` | R(ε₀), R(ε₁), R(ε₂), §6 (0 if NaN) |
| `edge_both_sweep.{delta_da, score}` | EdgeScore for an anchored pair with α(k) = f32(100 + e), α(k′) = 0 and m_a = 100, i.e. δ = (f32(100+e) ⊖ 0) ⊖ 100, for e = −0.300 … 0.300 in steps of 0.005 |
| `pre_site[k]`, `suf_site[k]` | Pre(k) and Suf(k) for k = 0 … max sink, §5 |
| `anchor_mass[k]` | α(k), with −1 = not anchored, §4.5 |
| `per_sink[]` | for each sink p: `vertex_weight[0..p]` (v(m), §8.3), `G` = the mixed per-sink distribution G_p of §8.5 as `{lowest, p[]}`, and `best` (its top score) |
| `H` | the merged distribution, §8.6. Element `p[i]` holds the mass at score `lowest + i` |
| `DeNovoScore` | DeNovoScore |
| `psms[]` | per PSM: `peptide`, `cumulative_nominal` (N₁ … N_L), `match` (Match, §7.2), `terminal_terms` (T_N + T_C), `RawScore`, `SpecEValue` |


## Spec-side verification done before hand-off

An implementation written by the spec author from SPEC.md alone, a throwaway not given to you,
reproduced the following:

- **Both intermediate files, bit for bit**: Π (m/z, intensity, rank), partitions, ρ, all edge
  integers, every Pre/Suf/α entry, every vertex weight, merged distributions to < 1e-9 relative,
  every DeNovoScore, 395 RawScores and 395 SpecEValues.
- **A 60-group sample of `search_n5` targets** (167 PSMs), with 0 differences.

The spec is therefore sufficient for exact agreement on these vectors. The §11 tolerances are
there to absorb legitimate f32 ordering differences in your implementation.
